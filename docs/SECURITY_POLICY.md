### 2.1 ข้อยกเว้นที่ต้องแจ้งผู้ใช้: บริการถอดเสียงของระบบ
SAFE ใช้ `SpeechRecognizer` ของ Android ซึ่งเป็นบริการของระบบ (ส่วนใหญ่คือ Google)
- SAFE เลือก **ถอดเสียงในเครื่อง** ก่อนเสมอ (`createOnDeviceSpeechRecognizer`, `EXTRA_PREFER_OFFLINE`)
- ถ้าเครื่องถอดภาษาไทยในเครื่องไม่ได้ SAFE จะใช้ตัวถอดเสียงปกติของระบบ ซึ่ง **ผู้ให้บริการอาจส่งเสียงไปประมวลผลบนเซิร์ฟเวอร์**
- การส่งนี้ทำโดยบริการของระบบภายใต้นโยบายของผู้ให้บริการ ไม่ใช่โดย SAFE แต่ต้องแจ้งผู้ใช้ไว้ในหน้ายินยอมและนโยบายความเป็นส่วนตัว (ทำแล้ว)
- 🔜 แผนเฟส 2: ฝังตัวถอดเสียงออฟไลน์ (เช่น whisper.cpp) เพื่อตัดข้อยกเว้นนี้ทิ้ง

## 3. สิทธิ์ของแอป (Permissions)

| สิทธิ์ | ใช้ทำอะไร | ขอตอนไหน |

## 5. ข้อมูลเทรนจากผู้ใช้ (Data Contribution)

ฟีเจอร์ "ช่วยเพิ่มข้อมูลให้ AI" มีขั้นตอนบังคับดังนี้:

1. ผู้ใช้ **ยืนยันเอง** ว่าเป็นมิจฉาชีพหรือไม่ (ไม่ใช้ผลของ AI เป็นป้ายอัตโนมัติ)
2. ข้อความผ่าน `PiiRedactor` แล้วผู้ใช้ **ตรวจ/แก้** อีกรอบก่อนบันทึก
3. ส่งออกเป็น CSV ได้เมื่อ **ผู้ใช้กดเอง** ผ่านหน้าบันทึกไฟล์ของระบบ (SAF)
4. ฝั่งทีมพัฒนา:
   - วางไฟล์ไว้ที่ `ml/data/contributed/` ซึ่ง **อยู่ใน .gitignore ห้ามขึ้น repo** (แม้ repo จะเป็น private)
   - เปิดตรวจด้วยตาก่อนเทรนทุกไฟล์: ลบแถวที่ยังมีชื่อคน ที่อยู่ หรือข้อมูลระบุตัวตน
   - เก็บไฟล์ต้นฉบับไม่เกิน 90 วันหลังรวมเข้าชุดข้อมูลหลัก แล้วลบ
   - รับข้อมูลเฉพาะจากผู้ที่ส่งให้ด้วยความสมัครใจ และบันทึกว่าได้รับเมื่อไหร่ จากใคร (เพื่อลบได้ถ้าเจ้าของขอ)
5. ห้ามนำข้อมูลที่ผู้ใช้ส่งมาไปใช้อย่างอื่นนอกจากพัฒนาโมเดลคัดกรองมิจฉาชีพ

## 6. การพัฒนาอย่างปลอดภัย (Secure Development)

- **กุญแจเซ็นแอป** (`*.jks`, `keystore.properties`): ห้ามขึ้น repo (อยู่ใน `.gitignore`) เก็บสำรอง 2 ที่แบบออฟไลน์ และใช้ **Play App Signing**
- **ห้ามมีความลับในโค้ด**: ไม่มี API key / token ใดๆ ในแอป (แอปไม่ต่ออินเทอร์เน็ตอยู่แล้ว)
- **ทุกการเปลี่ยนแปลงผ่าน Pull Request** และต้องมีอีกคนรีวิว โดยเช็กลิสต์:
  - [ ] ไม่เพิ่มสิทธิ์ใหม่ (ถ้าเพิ่ม ต้องแก้นโยบายนี้ใน PR เดียวกัน)
  - [ ] ไม่ log ข้อความบทสนทนา / เบอร์โทร / ข้อมูลผู้ใช้
  - [ ] ข้อมูลใหม่ที่บันทึกลงเครื่อง ผ่าน `PiiRedactor` และอยู่ในตารางข้อ 2
  - [ ] unit test ผ่าน (`ScamClassifierTest` ยืนยันว่าโมเดลในแอปตรงกับ Python)
- **ไลบรารี**: ใช้เฉพาะจาก Google Maven / Maven Central อัปเดตทุก 3 เดือน และดูประกาศช่องโหว่
- **โมเดล AI**: ไฟล์ `scam_model.json` สร้างจาก `ml/export_model.py` เท่านั้น ซึ่งตรวจความตรงกับ scikit-learn ก่อนเขียนไฟล์ทุกครั้ง

## 7. การรับมือเหตุการณ์ (Incident Response)

| ขั้น | สิ่งที่ทำ | กรอบเวลา |
|------|-----------|----------|
| 1. รับแจ้ง | ผ่านอีเมลใน [SECURITY.md](../SECURITY.md) หรือรีวิวบน Play Store | ตอบรับภายใน 72 ชม. |
| 2. ประเมิน | ข้อมูลผู้ใช้รั่วหรือไม่? กระทบกี่คน? | ภายใน 7 วัน |
| 3. แก้ไข | ออกเวอร์ชันแก้ / ถอดฟีเจอร์ชั่วคราว | ช่องโหว่ร้ายแรง: ภายใน 14 วัน |
| 4. แจ้ง | ถ้าเป็นการละเมิดข้อมูลส่วนบุคคลที่มีความเสี่ยง: แจ้ง สคส. (PDPC) ภายใน 72 ชม. ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 และแจ้งผู้ใช้ที่ได้รับผลกระทบ | ตามกฎหมาย |
| 5. ทบทวน | บันทึกสาเหตุ + ปรับนโยบายนี้ | หลังปิดเหตุ |

> หมายเหตุ: เพราะ SAFE ไม่มีเซิร์ฟเวอร์และไม่ส่งข้อมูลออก ความเสี่ยงหลักคือ (ก) ข้อมูลบนเครื่องที่ถูกขโมย/ปลดล็อก
> (ข) ไฟล์ CSV ที่ผู้ใช้ส่งออก (ค) ข้อมูลเทรนฝั่งทีมพัฒนา — มาตรการในข้อ 4–5 ออกแบบมาเพื่อสามข้อนี้

## 8. ความเสี่ยงที่ยอมรับไว้ (Known Limitations)

| ความเสี่ยง | ผลกระทบ | การจัดการ |
|-----------|---------|-----------|
| AI ตัดสินผิด (ปล่อยมิจฉาชีพเป็นเขียว) | ผู้ใช้อาจหลงเชื่อ | บอกชัดว่าเป็นเครื่องช่วยเตือน + แสดงคำแนะนำทุกครั้งที่ไม่ใช่สีเขียว |
| `PiiRedactor` ลบชื่อคน / ตัวเลขที่พูดเป็นคำไม่ได้ | ข้อมูลส่วนตัวหลงเหลือในข้อความ | บังคับให้ผู้ใช้ตรวจก่อนยืนยัน + ทีมตรวจซ้ำก่อนเทรน |
| ฐานข้อมูลไม่ได้เข้ารหัสแยก | ถ้าเครื่องถูก root/ปลดล็อก อาจอ่านได้ | อาศัยการเข้ารหัสของ Android (FBE) + sandbox ของแอป · พิจารณา SQLCipher ในเฟสถัดไป |
| บริการถอดเสียงของระบบอาจใช้คลาวด์ | เสียงออกจากเครื่องผ่านผู้ให้บริการ | แจ้งผู้ใช้ + ใช้แบบในเครื่องก่อนเสมอ + แผน whisper.cpp |
