# 🛡️ SAFE — Scam Alert For Everyone

แอป Android ช่วยเตือนภัยมิจฉาชีพทางโทรศัพท์ ออกแบบให้ผู้สูงอายุที่มีโทรศัพท์เครื่องเดียวใช้ได้
AI คัดกรองบทสนทนาทำงาน **ในเครื่อง 100%** · ฐานข้อมูลเบอร์ชุมชน (คล้าย Whoscall) เป็นทางเลือก ปิดไว้เป็นค่าเริ่มต้น

> ต่อยอดจากต้นแบบที่ใช้แข่ง depa Regional Coding & AI Competition (Arduino UNO Q + Python)
> โค้ดต้นแบบเดิมดูได้ที่ git tag [`v1-competition`](../../tree/v1-competition)

## 🚦 แอปทำอะไร

| ชั้นป้องกัน | ทำงานตอนไหน | วิธีทำงาน | สถานะ |
|------------|-------------|-----------|-------|
| 1. เตือนเบอร์อันตราย | ตอนสายเข้า | `CallScreeningService` ตรวจเบอร์ที่ไม่อยู่ในรายชื่อ กับ สมุดเบอร์ → ฐานข้อมูลชุมชน → กฎ กสทช. (+697 = 🔴, +698/ต่างประเทศ/ซ่อนเบอร์/รูปแบบผิด = 🟡) → ผลตรวจเบอร์ปลอมของเครือข่าย (STIR/SHAKEN) | พร้อมทดสอบ |
| 2. ตรวจหลังวางสาย | ทันทีหลังวางสาย | เมื่อแอปโทรศัพท์ของเครื่องอัดเสียงสายเสร็จ SAFE ถอดเสียง → วิเคราะห์ → เตือน | ⚠️ ต้องทดสอบบนเครื่องจริง |
| 3. ฟังผ่านลำโพง | ระหว่างคุย | เปิดลำโพง แล้ว SAFE ฟังจากไมค์และเปลี่ยนสีทันที | 🧪 ทดลอง (บางรุ่นระบบปิดไมค์ระหว่างสาย) |

ผลแสดงเป็น 3 สีเหมือนต้นแบบเดิม: 🔴 ≥ 70% · 🟡 40–69% · 🟢 < 40%
วิเคราะห์ **ทั้งบทสนทนาสะสม** และจำค่าสูงสุดไว้ (เคยแดงแล้วไม่กลับเป็นเขียวเอง)

**ตั้งค่าทีละขั้น (ลูกหลานช่วยตั้งให้ได้):** แสดงเองครั้งแรกหลังยอมรับนโยบาย และเปิดใหม่ได้จากหน้าแรก/ตั้งค่า
แจ้งเตือน → แอปคัดกรองสาย → วิธีเปิดอัดเสียงสาย**ตามยี่ห้อ** (Samsung, Xiaomi, OPPO/realme, vivo) → เปิดตรวจอัตโนมัติ + ปุ่มทดสอบ
"SAFE เห็นไฟล์อัดเสียงสายไหม" → ตั้งค่าแบตเตอรี่/ทำงานเบื้องหลังตามยี่ห้อ → ไมโครโฟน → สรุปสถานะ
(ถ้าเครื่องใช้แอปโทรศัพท์ของ Google จะบอกให้ข้ามการตรวจอัตโนมัติ เพราะไฟล์อัดเสียงอ่านไม่ได้)

**ใช้ได้โดยไม่ต้องติดตั้งแอป** (ใช้ "สมองฉบับ JavaScript" [`web/safe-core.js`](web/safe-core.js) ที่ให้ผลตรงกับแอปทุกตัวเลข):
- 🌐 **เว็บแอป** ([`web/`](web/)): ตรวจข้อความ/ลิงก์/เบอร์ ตอบ 5 ข้อ และ**เดโมจำลองสายเข้า** — คำนวณในเบราว์เซอร์ ไม่ส่งข้อมูลออก ใช้ได้ทั้ง iPhone และ Android
  ทดลองในเครื่อง: `python -m http.server 8765 --directory web` แล้วเปิด http://localhost:8765
- 💬 **บอต LINE** ([`line-bot/`](line-bot/)): ส่งต่อข้อความแปลก ๆ ให้บอต แล้วได้ผล 3 สี — รันบน Google Apps Script ฟรี วิธีตั้งค่า: [docs/LINE_BOT_SETUP.md](docs/LINE_BOT_SETUP.md)
- ทดสอบ: `node --test web/test/core.test.js line-bot/test/bot.test.js`

**ไม่ต้องใช้เสียงก็ตรวจได้:**
- 💬 **ตรวจข้อความ / ลิงก์**: แชร์ SMS หรือ LINE มาที่ SAFE (หรือวางข้อความ) → ผล 3 สีทันที + ตรวจลิงก์ (ลิงก์ย่อ, ไฟล์ .apk, อ้างหน่วยงานรัฐแต่ไม่ใช่ .go.th, ชื่อเว็บเลียนแบบธนาคาร/ขนส่ง/ร้านค้า, IP, punycode) · กดไมค์บนแป้นพิมพ์เพื่อพูดเล่าว่าคนที่โทรมาพูดอะไรได้
- 🆘 **ตอบ 5 ข้อหลังวางสาย**: แตะ ใช่/ไม่ใช่ (ให้โอนเงิน? ขอ OTP? ให้ติดตั้งแอป? ขู่/เร่ง? อ้างหน่วยงาน?) → ผล 3 สี อิงหลัก "ไม่เชื่อ ไม่รีบ ไม่โอน" · เสนอให้อัตโนมัติเมื่อถอดเสียงไฟล์ไม่สำเร็จ

**สมุดเบอร์ / รายงานเบอร์ (คล้าย Whoscall):**
- บันทึกเบอร์เป็น 🔴 มิจฉาชีพ / 🟡 สแปม / 🟢 ไว้ใจได้ + หมวด + โน้ต · ตั้ง "ตัดสายอัตโนมัติ" รายเบอร์ได้
- SAFE จดเบอร์ไม่รู้จักที่โทรเข้าไว้ 7 วัน → กด "รายงานสายเมื่อกี้" ได้ 1 แตะ (ไม่ต้องขอสิทธิ์ประวัติการโทร)
- วิเคราะห์ไฟล์เสียงหลังวางสายแล้วเป็นสีแดง → จับคู่กับเบอร์ที่โทรเข้า แล้วถามว่าจะรายงานไหม
- แชร์สมุดเบอร์ให้ครอบครัวผ่านไฟล์ (ลูกหลานตั้งให้พ่อแม่)
- **ฐานข้อมูลชุมชน (ไม่บังคับ)** ผ่าน Firebase: ส่งแค่ hash ของเบอร์ + ประเภท · ตรวจสายเข้าในเครื่อง เซิร์ฟเวอร์ไม่รู้ว่าใครโทรหาคุณ · เตือนเมื่อมีผู้รายงาน ≥ 3 คน
  ตั้งค่าตาม [docs/FIREBASE_SETUP.md](docs/FIREBASE_SETUP.md) — ไม่ตั้ง = ใช้แบบในเครื่องได้ครบ

**กันเบอร์ปลอม:** กฎ กสทช. (+697/+698/+66 ไม่มีต้นทาง) · รูปแบบเบอร์ผิดปกติ · STIR/SHAKEN (Android 11+, ถ้าค่ายส่งผลมา) ·
ถ้าเบอร์ดูปกติแต่เนื้อหาเป็นมิจฉาชีพ → เตือนว่า "เบอร์อาจถูกปลอม" · หน้าเบอร์ทางการ (1441, 1213, 191, 1185) ให้วางสายแล้วโทรกลับเอง

**ช่วยเพิ่มข้อมูลให้ AI:** ทุกบทสนทนาที่วิเคราะห์แล้ว ผู้ใช้กดยืนยันได้ว่า "มิจฉาชีพ / ไม่ใช่" + เลือกประเภท + แก้คำที่ถอดผิด
แล้วส่งออกเป็น CSV ฟอร์แมตเดียวกับ `ml/data/Dataset*.csv` เพื่อเทรนโมเดลรุ่นถัดไป

## 🧠 โมเดล AI

`ข้อความ → normalize → char n-gram (2–5) → TF-IDF → Naive Bayes → sigmoid calibration → %`

- ใช้ฟีเจอร์ระดับตัวอักษรอย่างเดียว เพื่อให้ Kotlin คำนวณได้ **ตรงกับ Python ทุกตัวเลข** โดยไม่ต้องมีตัวตัดคำไทย
  และยังทนต่อการถอดเสียงสะกดผิด
- Cross-Validation 5 รอบ (506 ประโยค รวมข้อมูลข่าว + สายจริงที่คล้ายมิจฉาชีพ): **accuracy 95.5% (±1.5%)** · precision 93.9% · recall 96.6%
  (ก่อนเพิ่มข้อมูลข่าว 96.3% ±3.7% บนชุดที่ง่ายกว่า — ชุดใหม่ยากขึ้นแต่ผลนิ่งขึ้น)
- Naive Bayes ค่าความเรียบ (alpha) 0.3 เลือกจาก CV 3 ชุดสุ่ม — ดีกว่าค่าเริ่มต้น 1.0 ทุกชุด (ดู `NB_ALPHA` ใน `ml/safe_text.py`)
- โมเดลเดิมทดสอบกับข้อมูลข่าวได้ 90.0% (พลาดมิจฉาชีพ 5/41) → เทรนรวมแล้วจับรูปแบบในข่าวได้
- `export_model.py` ตรวจทุกประโยคว่าสูตรที่ส่งออกต่างจาก sklearn ไม่เกิน 0.0001%
- `ScamClassifierTest` (Kotlin) ตรวจซ้ำอีกรอบกับ test vectors จาก Python

### เพิ่มข้อมูลจากผู้ใช้ (ข้อมูลโตขึ้นเรื่อย ๆ อย่างปลอดภัย)
ข้อมูลจากผู้ใช้ไม่เข้า AI อัตโนมัติ ต้องผ่านคนตรวจและด่านคุณภาพก่อน กันข้อมูลส่วนตัวหลุดและกันคนแกล้งใส่ข้อมูลผิด
1. วาง CSV ไว้ที่ `ml/data/inbox/` ตั้งชื่อให้รู้ว่าได้จากใคร เมื่อไหร่ เช่น `app_user01_2026-12-01.csv`, `line_2026-12-01.csv`
   - จากแอป: เมนู ส่งออกข้อมูล (CSV) · จากบอต LINE: Google Sheet → ไฟล์ → ดาวน์โหลด → CSV
2. `python merge_contributions.py` → ลบข้อมูลส่วนตัวซ้ำ · ตัดข้อความซ้ำ · เขียน `ml/data/review/pending.csv`
   - แถวที่ต้องตรวจ (`decision` = `check`): ป้ายขัดกัน · AI เห็นต่างจากป้ายมาก · อาจมีชื่อคน/ที่อยู่ · ยาวผิดปกติ
3. เปิด `pending.csv` เปลี่ยน `check` เป็น `keep` หรือ `drop` (Excel: บันทึกเป็น "CSV UTF-8")
4. `python merge_contributions.py --apply` → **ด่านคุณภาพ**: เทียบโมเดลก่อน/หลังบนข้อมูลเดิมชุดเดียวกัน
   - แย่ลงเกิน 1 จุดในตัวชี้วัดใดก็ตาม → ไม่รวม (ปรับเกณฑ์ได้ด้วย `--tolerance`)
   - ผ่าน → `ml/data/contributed/<ชื่อไฟล์ต้นทาง>.csv` · ต้นฉบับย้ายไป `inbox/done/` · บันทึกใน `review/merge_log.csv` · เทรนใหม่ให้อัตโนมัติ
5. รันชุดทดสอบ แล้ว commit เฉพาะ `scam_model.json` + test vectors — **ห้าม commit ข้อมูลผู้ใช้**
6. เจ้าของข้อมูลขอให้ลบ: ดูชื่อไฟล์ใน `merge_log.csv` → ลบไฟล์นั้นใน `contributed/` → `python train_model.py`

## 📱 Build แอป

1. ติดตั้ง [Android Studio](https://developer.android.com/studio) (มี JDK และ Android SDK มาในตัว) — ใช้ JDK ที่มากับ Android Studio ได้เลย (ทดสอบแล้วทั้ง JDK 17 และ 25)
2. **File → Open** แล้วเลือกโฟลเดอร์ `android/` รอ Gradle sync
3. ต่อมือถือ (เปิด USB debugging) แล้วกด ▶ Run
4. รัน unit test: คลิกขวาที่ `app/src/test` → **Run Tests** หรือ `./gradlew testDebugUnitTest`

### 🤖 Build อัตโนมัติบน GitHub (CI)
ทุกครั้งที่ push จะรันบน GitHub Actions ให้เอง ไม่ต้องมี Android Studio:
- **Android CI** ([.github/workflows/android.yml](.github/workflows/android.yml)): ตรวจ Gradle wrapper → รัน unit test ทั้งหมด (35 ข้อ) → build APK
- **ML check** ([.github/workflows/ml.yml](.github/workflows/ml.yml)): เทรนโมเดล + ตรวจว่าไฟล์ที่ส่งให้แอปตรงกับ scikit-learn

**ดาวน์โหลด APK ไปลองบนมือถือ:** GitHub → แท็บ **Actions** → **Android CI** → เลือก run ล่าสุดที่เป็น ✅ → เลื่อนลงไปที่ **Artifacts** → `safe-debug-apk`
(แตกไฟล์ zip → ส่ง `app-debug.apk` เข้ามือถือ → เปิดติดตั้ง ต้องอนุญาต "ติดตั้งแอปที่ไม่รู้จัก" ครั้งแรก · ไฟล์เก็บไว้ 14 วัน)
APK debug ทุกรุ่น (จาก CI หรือ build เอง) เซ็นด้วยกุญแจทดสอบเดียวกัน ([android/app/debug.keystore](android/app/debug.keystore)) จึง**ติดตั้งรุ่นใหม่ทับรุ่นเก่าได้เลย ข้อมูลไม่หาย**

หรือใช้คำสั่ง:
```bash
gh run download --repo PanuwatKi/SAFE-i-new-gen --name safe-debug-apk
```

### 🗄️ เปลี่ยนโครงสร้างฐานข้อมูล (Room)
ข้อมูลผู้ใช้ (สมุดเบอร์, ประวัติ) ต้องไม่หายเมื่ออัปเดตแอป:
1. แก้ Entity → เพิ่ม `version` ใน `@Database` ขึ้น 1
2. เพิ่ม `AutoMigration(from = เดิม, to = ใหม่)` (หรือ `Migration` ที่เขียนเองใน `MIGRATIONS` ถ้าเปลี่ยนชื่อ/ลบคอลัมน์)
3. push → CI สร้างไฟล์ schema ใหม่ → ดาวน์โหลด artifact `room-schemas` แล้ว commit ลง `android/app/schemas/`
   (ถ้ามี Android Studio: build ในเครื่องแล้ว commit ไฟล์ที่เกิดขึ้นได้เลย) — CI จะ fail ถ้าลืมข้อนี้

ต้องการ: minSdk 26 (Android 8) · ฟีเจอร์ตรวจไฟล์เสียงต้อง Android 13+ · การเตือนตอนสายเข้าต้อง Android 10+
